# WaterSort

A small ad-free water sort puzzle for iPhone. Built for family use.

## Setup

1. In Xcode, **File → New → Project → iOS → App**.
   - Product Name: `WaterSort`
   - Interface: SwiftUI
   - Language: Swift
   - Minimum deployment: **iOS 17** (required for `@Observable`).

2. Drag every `.swift` file from this folder into the project, replacing the
   default `ContentView.swift` and `WaterSortApp.swift`.

3. Drag `Levels.json` into the project. **Make sure "Copy items if needed" and
   "Add to target: WaterSort"** are both checked, otherwise the bundle lookup
   in `GameState.loadLevels()` will fall through to the placeholder level.

4. Build and run. There's a `#Preview` macro on `ContentView` so the canvas
   should also work.

## Distributing to family

Cheapest path with the dev account you already have for TagPilot:

1. Archive the app: **Product → Archive**.
2. In Organizer, **Distribute App → TestFlight Internal Only** (or external if
   you want a public link).
3. Add Lita and any other Apple IDs as internal testers in App Store Connect.
   Each device installs TestFlight once and then auto-receives builds.

Builds expire after 90 days, so you'll re-archive once a quarter. No App Store
review needed for internal testers.

If you don't want to mess with App Store Connect, plain free-provisioning works
too — just plug each device in, hit Run, and it lasts 7 days per install (or
1 year with your paid account). TestFlight is way less friction.

## How levels work

`Levels.json` was generated by `generate_levels.py` (in the repo root of this
package). It uses reverse-pour from the solved state, which guarantees every
level has a solution. To regenerate or extend:

```sh
python3 generate_levels.py
```

Tweak the `configs` list at the bottom of the script to adjust difficulty
buckets. The current pack has 36 levels, scaling from 2 colors up to 9.

## Architecture (one-screen tour)

- `Models.swift` – `Level` and `LevelPack` Codable types.
- `Palette.swift` – the 12-color palette with paired SF Symbols (so each
  color is also distinguishable by shape — useful for kids and colorblind
  players).
- `GameState.swift` – `@Observable` model holding the current vials, selection,
  undo stack, and progress. All game rules live here.
- `VialView.swift` – pure SwiftUI vial: glass outline, stacked liquid bands,
  symbol overlay, lift-on-select animation.
- `ContentView.swift` – toolbar (restart / undo), responsive vial grid, win
  alert, prev/next level chevrons.

## Things deliberately NOT built

You can add these later if anyone actually wants them:

- Sound / haptics (one `.sensoryFeedback(.success, ...)` on win is one line)
- Themes / palette switcher
- Hint button (would need to bundle the BFS solver from `generate_levels.py`)
- iCloud sync of progress
- Game Center, leaderboards, achievements
- A level select screen with a grid of stars
- Particle effects on win
- Procedural level generation at runtime

The current code stays under ~400 lines on purpose. Easy to read, easy to
hand to a kid for a "why is this red" debugging session.

## Known rough edges

- The pour animation is a simple band-fade transition, not a realistic liquid
  arc. Looks clean but not flashy. If you want the "tilt + pour" effect,
  you'll want a custom `Animatable` modifier with a tilt angle and a Bezier
  liquid stream — non-trivial, maybe a weekend on its own.
- No accessibility labels yet on vials. `VialView` is a good place to add
  `.accessibilityLabel("Vial \(n), top color \(name)")` if VoiceOver matters.
- Win detection runs after every pour but the alert is gated on a 0.4s delay
  so the final animation reads. Adjust in `ContentView`.
