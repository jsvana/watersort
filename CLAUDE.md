## Build & Deploy

The Xcode project is generated by [xcodegen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. After adding/removing source files or changing build settings, regenerate:

```sh
xcodegen generate
```

All builds, tests, and device operations go through the `xc` skill (`~/.claude/skills/xcode-build/scripts/xc`). Builds target the physical device **theseus** — never the simulator.

| Task | Command |
|------|---------|
| Build | `xc build` |
| Build + install + launch on theseus | `xc deploy` |
| Quality gate (format → lint → build) | `xc quality` |
| Pull crash logs | `xc crashes WaterSort` then `xc crash <file.ips>` |

Deployment target is iOS 17 (required for `@Observable`). Signing uses team `7UE4RDLUSX`, bundle id `com.jsvana.watersort`.

## Levels

`Levels.json` is generated by `generate_levels.py` using reverse-pour from solved state, which guarantees every level has a solution. To regenerate:

```sh
python3 generate_levels.py
```

Tweak the `configs` list at the bottom of the script to change difficulty buckets. The bundled pack has 36 levels scaling from 2 to 9 colors.

`Levels.json` must be in the app bundle — `GameState.loadLevels()` falls through to a hardcoded placeholder level if the bundle lookup fails. The xcodegen spec includes it as a resource via the target's `sources` entry; if you rename or move it, update `project.yml` and regenerate.

## Architecture

The whole game is ~400 lines on purpose. Five Swift files in the project root:

- **`Models.swift`** — `Level` and `LevelPack` `Codable` types. A vial is `[Int]` of color indices, bottom-to-top; empty array = empty vial.
- **`Palette.swift`** — 12-color palette. Each color is paired with a distinct SF Symbol so vials are distinguishable for colorblind players and pre-readers. `palette[colorIndex % palette.count]` is the lookup pattern; color indices in `Levels.json` index into this array.
- **`GameState.swift`** — `@Observable` model. Owns levels, current vials, selection, undo stack, win flag, and progress. **All game rules live here.** Pour logic in `attemptPour` enforces: top color match, contiguous same-color block from src top, capacity check on dst. `vialCapacity` is `4`. Progress is persisted to `UserDefaults` under `"currentLevelIndex"` only when the player advances (not on every pour).
- **`VialView.swift`** — pure SwiftUI vial rendering. Glass outline + bottom-up liquid bands + symbol overlay + lift-on-select animation. Frame is hard-coded `56×200`.
- **`ContentView.swift`** — toolbar (restart/undo), responsive vial grid (column count adapts to vial count), win alert (gated 0.4s after pour so the final animation reads), prev/next chevrons.

`@State private var game = GameState()` in `ContentView` is the single owner — no environment injection, no DI.

## Things deliberately NOT built

The README lists features intentionally left out: sound/haptics, themes, hint button, iCloud sync, Game Center, level select grid, particle effects, runtime level generation. Don't add these unless explicitly asked.

## Known rough edges (from README)

- Pour animation is a band-fade, not a tilt+stream. A realistic pour would need a custom `Animatable` modifier.
- No accessibility labels on vials yet. `VialView` is the place to add `.accessibilityLabel(...)`.
- Win alert delay is hardcoded at 0.4s in `ContentView`.
